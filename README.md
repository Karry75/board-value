## 技术速览

- **形态**：单文件静态看板（HTML + JavaScript + ECharts），数据以离线快照形式随页面加载，纯前端渲染、无后端依赖。
- **原理**：业务库（阿里云 AnalyticDB）→ Python 抽取/构建管线 → 脱敏聚合快照 → 静态页面；页面打开即渲染，支持按维度筛选与下钻。
- **用途**：网点价值与财务收支看板：网点收益结构与收支结构分析。
- **脱敏**：公开发布版本已移除数据库连接信息、账号口令与个人敏感字段，仅保留聚合指标。


> 面向两轮车「换电 + 租车」业务的**网点价值评估**与**财务收支**看板：把分散在业务库与基础库中的网点经营数据，统一聚合成可横向比较的网点价值评分与收支视图，支持按城市 / 代理商 / 网点逐层下钻。

`Python 3.11` · `Flask` · `PyMySQL` · `原生 JS / ECharts（本地化，零外网依赖）` · `GitHub Pages 静态快照`

---

## 1. 它解决什么问题

| 痛点 | 本看板的做法 |
|------|--------------|
| 网点数量多、经营口径散，无法横向比较 | 统一聚合口径 + 网点价值评分模型，输出分值、分档与排名 |
| 收入与支出分散在不同表，对不上账 | 按网点 / 时间维度聚合收支明细，金额统一口径后展示 |
| 业务库是生产库，不能被看板拖慢 | 全链路**只读**查询，统一走数据访问层，不做任何写入 |
| 值班期间业务库抖动、网络中断 | 三重降级：内存缓存 → 本地落盘缓存（回放最后一次真实数据）→ 演示数据，页面顶部徽标标识当前数据来源 |

## 2. 技术原理

### 2.1 数据链路

```
浏览器 → bvapi/routes.py (Flask Blueprint, /api/*) → bvcore/metrics.py (聚合 + 评分) → AnalyticDB（MySQL 协议，只读）
```

### 2.2 可用性设计（断库不白屏）

- 聚合结果带 **5 分钟内存缓存**（`_SITE_VALUE_TTL = 300`），避免同一个大查询被反复触发；
- 查询结果同时落盘到 `data/cache/*.json`；服务重启或业务库不可达时直接回放最后一次真实数据，页面标注 `cache` 来源；
- 内存与落盘缓存都不可用时，回落到 `bvcore/demo.py` 演示数据，页面标注 `demo`，不出现白屏或报错。

### 2.3 口径与单位

- 库内金额以**分**存储，对外统一转换为**元**后再参与评分与展示，避免前端重复换算；
- 网点价值评分由多个经营指标加权合成，权重与指标定义集中在 `bvcore/metrics.py`，输出分值、分档与明细。

### 2.4 前端与静态快照

- `web/`：本地运行时的前端页面，ECharts 等资源全部本地化，不依赖外网 CDN；
- `docs/`：GitHub Pages 使用的**静态只读快照**，前端改为直接读取 `docs/data/*.json`，不携带任何数据库访问能力。

## 3. 目录结构

```
board-value/
├── app.py                  # Flask 入口（默认端口 8093）
├── bvapi/routes.py         # /api/* 路由
├── bvcore/metrics.py       # 数据聚合口径与网点价值评分模型
├── bvcore/demo.py          # 演示数据兜底
├── web/                    # 本地运行前端（含本地化 ECharts）
└── docs/                   # GitHub Pages 静态快照（index.html + data/*.json）
```
